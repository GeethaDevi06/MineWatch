# MineWatch V2

### Interactive Mining Production, Safety & Environmental Analytics

> MineWatch analyses mining production, productivity, safety, environmental and economic
> data to identify trends, recurring issues and areas requiring attention through an
> interactive analytics dashboard.

Inspired by the SIH 2026 problem statement **SIH26024 — Coal Mine Governance & Compliance**.

---

## ⚠️ Project Positioning

MineWatch is a **student-built academic analytics prototype**. It is **not**:

- an official government compliance system
- an official mining safety system or safety score
- an accident prediction system
- a real-time mine control system
- a replacement for mining inspectors
- an official SIH implementation

All data used by this project is **synthetic / project-generated** (see [Dataset](#dataset)
below). Correlations and comparisons shown throughout the dashboard indicate association,
not causation.

---

## Problem

Mining generates large amounts of operational, safety, environmental and compliance-related
data. Analysing these records manually makes it difficult to identify trends, recurring
issues, and areas that may need attention.

## Solution

MineWatch provides an interactive EDA (Exploratory Data Analysis) platform — a cleaned,
derived-metric-enriched dataset, a full Jupyter EDA notebook, and a Streamlit dashboard —
for analysing production, productivity, safety, environmental impact, energy, waste and
economics across a multi-year, multi-mine dataset.

## Features

- **Interactive dashboard** with sidebar navigation across 17 pages: Overview, Production,
  Reserves, Productivity, Energy, Waste, Safety Trends, Violations, Risk Heatmap,
  Environment, Economics, Regional Performance, Forecasting, Mine Explorer, AI Insights,
  Data Explorer, and About Project.
- **Global filters**: Mine, Region, State, Mine Type, Commodity, Year, Month, Violation
  Category, Incident Category, Severity — plus a one-click Reset Filters button. Filters
  never crash the app; an empty selection shows a friendly message instead.
- **KPI cards** for mines, production, safety incidents, violations, revenue, profit,
  productivity and pending actions.
- **12+ interactive Plotly visualizations**: production trend, reserve depletion,
  productivity index, commodity price vs production, production vs environmental impact,
  a year × risk-factor heatmap, cost vs revenue, energy & waste intensity, safety trends,
  regional bubble chart, and more — all with hover, zoom, pan and legend toggling.
- **Rule-based Key Findings engine** that computes real percentage changes directly from
  the (filtered) data — nothing is hard-coded.
- **"What Changed?" comparison** between the most recent year and the prior year in the
  current filter selection.
- **Mine Explorer** with a per-mine profile, KPIs, trend tabs, and a "Generate Mine
  Insight" button.
- **AI Insights (optional)**: sends only a small structured JSON summary (never the raw
  dataset) to an LLM for a short analytical observation. If no API key is configured, or
  the request fails, the app automatically falls back to a rule-based observation — the
  dashboard always works.
- **Data Explorer**: view the cleaned/filtered dataset, descriptive statistics, and
  download the filtered data as CSV. A visible data-cleaning methodology strip helps
  explain the pipeline during a viva.
- **Experimental forecasting**: a simple linear trend model, clearly labelled as
  experimental and not a production-certain prediction.

## Dataset

- `minewatch_data.csv` — **3,272 rows × 36 columns**, generated by `generate_dataset.py`
  with a fixed random seed (`42`) for full reproducibility.
- **30 fictional mines** (`MINE-001`–`MINE-030`) across 10 Indian regions/states, 5
  commodities (Coal, Iron Ore, Bauxite, Limestone, Copper Ore), and 3 mine types
  (Open Cast, Underground, Mixed).
- **Monthly observations from January 2016 to December 2024** (9 years × 12 months × 30
  mines = 3,240 base rows), plus **32 intentionally duplicated rows** (~1%) to give the
  EDA notebook genuine duplicate-detection work.
- All fields are **synthetic / project-generated** — there is no real public mining
  dataset backing these exact records. Field names and structure are loosely inspired by
  the kinds of variables found in public sources such as MSHA (Mine Safety and Health
  Administration) and USGS mineral resource datasets, but no real records from those
  sources are used or reproduced.
- **Realistic relationships are built in**, not random noise:
  - `Profit = Revenue − Operating_Cost` (exact, by construction)
  - `Revenue` scales with `Production × Commodity_Price`
  - `Energy_Consumption` and `Waste_Generation` scale with `Production` (plus a mine-type
    overhead factor for Underground/Mixed mines)
  - `Remaining_Reserve` only ever decreases over time, by the extracted `Production`
  - `Productivity_Index = Production / Working_Hours`
  - Each mine has its own long-run **safety "personality"** (increasing, decreasing,
    stable, or spiky incident trend)
  - Violations relate to `Corrective_Actions`, some of which remain `Pending_Actions`
- **Intentional data-quality issues** for the EDA notebook to work with:
  - ~0.2–0.5% missing values in `Working_Hours`, `Energy_Consumption`, `Commodity_Price`,
    `Environmental_Impact`
  - Inconsistent category labels, e.g. `Open Cast` / `Open-Cast` / `open cast` /
    `OPEN CAST`, and mixed-case violation categories
  - A handful of realistic outliers in production, energy, waste and safety incidents
  - 32 fully duplicated rows

## How to Run

```bash
pip install -r requirements.txt

# 1. Generate the dataset (creates minewatch_data.csv)
python generate_dataset.py

# 2. Launch the dashboard
python -m streamlit run app.py
```

The dashboard opens at `http://localhost:8501` by default.

To explore the EDA notebook:

```bash
jupyter notebook MineWatch_EDA.ipynb
```

## AI Setup (Optional)

1. Copy `.env.example` to `.env`.
2. Get a free key at https://aistudio.google.com/app/apikey and set:
   ```
   GEMINI_API_KEY=your_actual_key
   ```
3. Restart the app. The **AI Insights** page will now call the Gemini API with a small
   structured JSON summary (never the raw dataset) and label its output as
   "AI-generated analytical observation."

If no key is set, or the API call fails for any reason, the app automatically shows a
**rule-based analytical observation** instead — the dashboard is fully functional either
way.

## Methodology Summary

```
Mining Dataset (raw CSV)
      ↓
Duplicate removal
      ↓
Category normalization (Mine_Type, Violation_Category)
      ↓
Missing-value treatment (per-mine median imputation)
      ↓
Derived metrics (Energy_Intensity, Waste_Intensity, Incident_Rate_per_1000h)
      ↓
Exploratory Data Analysis (notebook)
      ↓
Interactive visualizations (dashboard)
      ↓
Mine-level analysis (Mine Explorer)
      ↓
Rule-based / AI-assisted analytical findings
```

## Limitations

- This is an **academic prototype** built for a college EDA project — not production
  software.
- The dataset is **entirely synthetic**; it does not represent any real mine, company, or
  government record.
- MineWatch is **not** an accident prediction system — the Safety pages perform
  *historical* analysis only.
- MineWatch is **not** an official compliance score. Where a composite score is shown, it
  is explicitly labelled the **MineWatch Project-defined Analytical Indicator**, with its
  components disclosed.
- **Forecasting is experimental** (a simple linear trend) and does not predict actual
  future production with certainty.
- Correlation and scatter-plot relationships shown throughout indicate **association, not
  causation**.
